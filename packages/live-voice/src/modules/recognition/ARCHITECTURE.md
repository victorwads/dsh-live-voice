# Recognition module

`engines/browser/BrowserRecognitionEngine.ts` adapts browser speech recognition and reports local-pack/browser capabilities. `engines/qwen/QwenRecognitionEngine.ts` and `engines/whisper/WhisperRecognitionEngine.ts` adapt local-first HTTP recognition; host bridges live beside the relevant adapters (Whisper here, shared Qwen configuration in `../core/qwen`). `components/RecognitionCapabilityStatus.tsx` and engine settings UI present capability and configuration states.

`vad/` owns the experimental browser Silero pool, worker inference, AudioWorklet capture and streaming resampling. Silero is the default where assets are available; explicit `voiceDetectionEngine: "energy"` opts out. One lazy inference session serves independent source states and bounded fair queues. Model/runtime assets are packaged and exposed by the application boundary; HTTP engines consume detector frames without owning tracks. See [Silero VAD](../../../../../docs/SILERO-VAD.md).

Shared Browser recognition borrows the meter-owned live audio track and reuses it across native restarts/reset; it never stops that track. External-audio support is independent of local-pack availability and remote-processing opt-in. A bounded same-origin srcdoc probe first verifies a known, denied microphone Permissions Policy, then uses the frame constructor and an ended synthetic canvas video track: only synchronous InvalidStateError validates the overload. Legacy ignored arguments, missing policy introspection, CSP/DOM failures and cancellation fail closed; start.length and OS/UA are not capability signals. The probe aborts immediately and releases its own frame/track. Meeting discovery happens before meter.start; native recognition begins only after capture provides the track.

Distinguish microphone capture and permission from recognition engine availability. Do not infer feature support merely from operating system. Bound audio and host requests, keep host-only code out of the browser bundle, and abort/ignore stale results after cancellation. Recognition language and voice-command phrases are independent of the interface locale. Browser simulations are not a physical microphone or model acceptance test.
